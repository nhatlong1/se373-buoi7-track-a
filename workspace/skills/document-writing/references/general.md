# General Document Template

**Use when:** no other template fits, or the user explicitly wants an unstructured document. This template is deliberately permissive — it constrains quality, not shape.

**What this template is for:** a document whose structure is not predetermined. The writer chooses the shape, but the reader still deserves a clear purpose, a clear answer, and honest evidence.

---

## How to use this template

You are free to write this document in whatever form serves its purpose. There is no required section list. But hold to the following:

1. **Start from the purpose, not from a heading.** Before writing, state in one sentence what this document is for and who reads it. That sentence determines the shape.
2. **Choose the structure deliberately.** If you are unsure, the default below is a reasonable starting point. Adapt it, and drop sections that would be empty.
3. **Keep the quality floor.** The writing rules in `SKILL.md` apply in full: active voice, concrete language, no hedges, traceable claims, no invented facts, consistent terms, numbered exhibits, metadata block.
4. **Do not pad.** A short document that answers the question beats a long one that circles it. If a section would contain only one sentence, write the sentence and drop the heading.

---

## Default structure (adapt freely)

Use this as a starting point, not a requirement.

```markdown
# <Title>

| Field | Value |
|---|---|
| Author | <name or agent> |
| Date | <YYYY-MM-DD> |
| Version | <v1.0> |
| Status | Draft / In Review / Final |
| Audience | <who reads this> |

## Summary

<Three to five sentences. The answer, not the topic. If the reader
stops here, they should have the point.>

## Context

<What situation produced this document. What the reader already knows
and does not need repeated. What is in scope and out of scope.>

## <Main body>

<The substance. Organize by the reader's questions. Use subsections,
tables, and lists as the content requires.>

## Discussion

<Interpretation, trade-offs, implications. Optional if the body already
covers it.>

## Conclusion

<What it means. What the reader should do or decide.>

## Limitations and open questions

<What was not checked, what is uncertain, what would change the
conclusion.>

## References

<Sources, with enough detail to retrieve them.>

## Appendix A: <optional>

<Raw data, long listings, glossary, full transcripts.>
```

---

## Freedom checklist

Before delivering, confirm you have not over-constrained or under-delivered:

- [ ] The structure matches the purpose. A how-to is not written as an essay; a decision memo is not written as a tutorial.
- [ ] The reader can find the main point without reading linearly.
- [ ] Nothing is included "for completeness" that the reader will not use.
- [ ] The document is as long as it needs to be and no longer.
- [ ] The metadata block is filled in.
- [ ] Every claim that could be checked has a source or is labelled an assumption.
